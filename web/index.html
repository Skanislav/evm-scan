One call reads all of it, at one block.
eth_call with no to address, carrying the lens's creation code as the payload — the constructor returns the answer, so a contract becomes a pure function with no address to trust and no upgrade key
native balance, ERC-20 balances and allowances, ERC-165 detection, NFT ids and URIs, ERC-721Enumerable walking, code hash and the EIP-7702 delegation target — one round trip, one consistent snapshot, instead of a hundred calls landing at a hundred different blocks
the reply is treated as contract code, so EIP-170 caps it at 24 576 bytes; too large a portfolio fails outright rather than truncating, and the client halves the batch when a node says no
4
The nonce has to come separately.
the EVM has no opcode for another account's nonce, so no contract — deployless or not — can report one. eth_getTransactionCount alongside the call, and the answer says whether that read landed rather than printing a confident 0
5
Integers become amounts, then a value.
a balance is an integer in the token's own decimals — 18 for ether, so wei, and 1 gwei is 10⁹ of them; 6 for most stablecoins. Scaled by the decimals that same call returned, never by an assumption
then priced from the chain: a Chainlink feed, a Uniswap v3 TWAP, or a spot pool — whichever is defensible, tagged HIGH / MEDIUM / LOW, with the route shown. Nothing defensible means no price at all, never a zero
Every read inside that one call is a staticcall with capped gas and capped returndata, so nothing a hostile token does can revert the batch. A token that stays silent comes back as unknown — never as a balance of nought, because rendering a failed call as zero is a bug, not a rounding error.

03 · Where it came from

Three separate claims sit behind the table above, and they are not equally strong. Saying which is which is the product.

Which contracts
Found by scanning this node's logs for the account, and only among contracts somebody promoted or paid to index. They come from the committed index: a merkle root published on-chain with a challenge window, so a reader can check a row without trusting this server.
The balances
Live reads at head through a lens contract that is never deployed — no address to trust, no upgrade key. Never summed from Transfer events, which rebasing and fee-on-transfer tokens make wrong. Point the page at your own RPC and this deployment reads none of it.
What is missing
A snap-synced node serves logs only back to a history floor, so anything older is unreadable here and history_complete stays false rather than implying coverage. Contracts nobody promoted are not indexed at all — a miss means "not indexed", never "no balance".

    05 · Check it yourself

    The index is committed on-chain as a merkle root with a challenge window. Nothing above has to be believed — which is exactly why publishing it permissionlessly is safe.

    recompute the leaf, replay the proof, call verifyInclusion on-chain
    evmscan-verify -epoch <id> \ -account <0x…>

    Check the filter against the chain, not against us

    A file served over HTTP is vouched for by whoever served it — ask the same daemon for the bytes and for their digest and a lying one agrees with itself. So evmscan-verify -filter downloads the .xorf, reads the latest finalized epoch off-chain, fetches the manifest that epoch named, and compares. Without that step the on-chain digest is decoration.

    You can go further and rebuild it yourself from the published snapshot — no database, no node. Measured against the hosted mainnet index: 773 948 accounts and 857 417 pairs compile to 974 918 bytes at 1.14 bytes per key, against 50 MB for the gzipped table it came from. Fifty-one times smaller, for the one question a portfolio read actually asks.

    The limit is the URI scheme, and it is worth saying out loud: over ipfs:// the URI is the content, so the commitment fixes the document; over https:// it fixes only the address — the publisher committed to naming that URL, not to what it serves. Nothing here publishes to IPFS yet, so the loop is one hop shorter, not closed. The verifier prints which one it followed.

    Or read it with no evm-scan code at all

    The same answer is an ENS text record and an ERC-3668 gateway response — including evmscan.uri, which hands back the committed pointer verbatim rather than parsing it, because a resolver that picked documents apart would be committing itself to a format it cannot verify. Any viem or ENS client can fetch it; a gateway can withhold an answer but cannot forge one, and cannot serve a stale epoch.

    What we do not claim

    Prices from a DEX TWAP are manipulable with capital and time, and a spot price is manipulable within a block — the tier says which one you are looking at. Candidate ranking is event count and distinct blocks, crude on purpose, which is why auto-promote is off by default. ERC-1155 balances are per token id, so the index-driven views report none rather than a misleading zero.

    and if you find it wrong

    A commitment is optimistic: it finalizes on its own unless somebody bonds a challenge inside the window. Verifying a root is only worth something if disagreeing with it does something, so this is where the page has to be specific.

    What the rules can and cannot become

    Bonds, window, minimum funding and reward per block are fixed at deployment and have no setters; the arbiter cannot be reassigned. Changing any of them means deploying a new registry, so a deployment's rules are fully stated by one event and you can read the mode yourself from oracle() and arbiter().

    On a chain with no oracle deployment the fallback is local-arbiter mode: bonds in wei and one key settling disputes. That is a trusted deployment wearing a permissionless write path — the deploy tool says so in capitals, and this page would say so here.

    Be clear about the ceiling: UMA's DVM is a human vote, not a fraud proof. What it buys is that no single key decides and the deployment has no admin path at all. A real fraud proof would mean proving a log's existence on the source chain from another chain, which is out of scope here.
